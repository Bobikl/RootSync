# RootSync

面向已 ROOT Android 手机的局域网 rsync 同步工具，依据
`Android_ROOT_rsync_开发大纲.md` 开发。当前版本为 arm64 技术验证 APK。

## 当前版本（0.2.41）

- Kotlin、Jetpack Compose、Material 3；`compileSdk/targetSdk 36`，适配 Android 15/16；
- APK 内置经上游签名验证的 **rsync 3.4.4 arm64**，无需额外安装 ROOT rsync 模块；
- 内置 arm64 `syncmeta`，快照并恢复目录 mtime；两个原生 ELF 均使用 16 KB LOAD 对齐；
- 支持“只发送”“只接收”和“双向同步”，双向模式按较新修改时间收敛；
- 三种方向均可选择“全部内容”或“指定时间至今”，时间范围通过 NUL 分隔的精确文件清单交给 rsync；
- 多设备配置：每台设备分别保存地址、密钥、方向、同步范围、起始时间和本机目录；
- Android NSD/mDNS 与 UDP 8874 双通道自动发现，点击设备后由对方确认连接；
- 扫描时申请附近设备权限、绑定 Wi-Fi 网络并启用组播接收，修复部分 Android 16/小米设备扫描不到的问题；
- 默认设备名称读取系统“设备名称”，不再使用厂商与型号拼接；
- 本机密钥支持手动自定义，最少 6 位；
- 已配对设备按稳定设备 ID 长期信任，覆盖安装、密钥轮换和 DHCP 地址变化后自动恢复连接；只有主动删除设备才解除信任；
- 已信任设备使用独立控制令牌认证策略、服务准备、进度和密钥轮换消息；旧配置覆盖升级时自动迁移令牌；
- 配对设备的方向策略会同步到另一端，并自动换算为另一端的相反本机动作；
- 每次传输前请求远端按正确方向准备 `send` 或 `receive` 模块，使任意一端都能主动发起发送或接收；
- 已配对设备不再在控制请求失败时复用端口上的旧 rsync daemon；每次任务使用独立临时密钥，会话结束后停止临时服务，避免多设备之间连接到上一设备策略的目录；
- 本机任务与对方发起的任务不再共用可操作状态；只有本机发起的传输才能暂停或取消，延迟包、其他设备消息和对方结束消息不会提前解锁本机任务或误改旧传输记录；
- 配对与服务准备请求会持续重试到用户决定或超时，最终任务结束消息增加 ACK 和限时重发；远端心跳失联释放时间由 15 分钟缩短为 90 秒，降低 UDP 丢包造成的假忙碌和长时间锁定；
- 捕获 Android 12+ 后台前台服务启动限制：系统拒绝时停止临时 daemon、拒绝本次准备并发布“打开应用后重试”通知，不再让局域网消息协程崩溃或在无前台保护时继续接收；Android 15 数据同步超时时会清理接收端 daemon 会话，WakeLock 在长任务中定时续期；
- 删除引擎层所有未经确认的接收目录自动创建路径；本机主动只接收、双向同步或手动启动接收服务时，目录缺失都会先弹窗，只有明确选择“创建并继续”后才执行 ROOT mkdir；
- 生命周期 watchdog 同时检测真实 rsync/daemon 活动；任务和服务均结束后约 10 秒自动退出，不再因 Android 仍缓存应用进程而长期残留每 2 秒唤醒的 `sh`。完整性校验 rsync 也写入受校验 PID 并复用 watchdog；
- 设备配置改为逐条容错解析并保留上一份 JSON 备份；单条配置损坏不再清空全部设备，主配置损坏时可恢复备份。切换到没有记录的设备时也不会错误显示其他设备的旧传输记录或时间范围；
- 每个 ROOT shell 通道增加独立互斥锁，同一通道的命令按顺序执行，`activeProcess` 不再被并发命令覆盖；暂停和取消仍使用独立控制通道，可准确结束当前传输进程；
- 修改并停顿输入本机服务端口后会重新注册 NSD/mDNS 服务，扫描结果不再持续广播应用启动时的旧端口；输入过程增加防抖，避免逐字符反复注销和注册；
- 多设备服务准备请求改为显式互斥调度；一台设备等待目录创建决定时，其他设备会立即收到“本机忙碌”，不再因串行 Flow 被阻塞且请求去重后一直无响应；
- 同步范围下新增“快速比较/严格内容校验”：严格模式向预览、总量统计和正式 rsync 全程加入 `--checksum`，可发现路径、大小、修改时间均相同但内容不同的文件；快速模式保留大型目录性能，并把完成提示准确限定为“本次实际传输文件校验通过”；
- 差异预览提供独立大面板，逐项显示发生变化的实际文件路径和目录；远端差异计数改用累计序号与结束总数校准，并对逐文件 UDP 状态消息限流，避免大量文件时丢包导致双方数量相差一个数量级；
- 传输前用零写入 dry-run 统计上传量与下载量；进度卡片分别显示同步总量、已上传和已下载数据，进度按实际传输字节计算；
- rsync `-h` 输出与界面容量统一按十进制 SI 单位换算，修复大型目录的同步总量与实际传输量相差约 7.37% 的问题；
- 配对设备必须先通过实时 UDP 在线探测才能预览、传输或继续任务；设备离线时操作按钮直接禁用，开始前还会再次主动确认；
- 任务执行或在线确认期间，同步页的设备、扫描、连接参数、策略、时间范围、目录与保存按钮全部锁定，仅保留暂停传输或取消预览；
- 接收端目录不存在时不再静默创建或直接报错：接收设备弹窗询问是否创建，发送设备同步显示“对方正在选择操作”；拒绝或超时不会创建目录或写入文件；
- 主进度条直接引用同步总量、已上传和已下载形成的现有字节进度，不再被 rsync 百分比回调覆盖；
- 正在传输的文件与目录每 3 秒刷新一次，既能确认任务仍在工作，也避免高速传输时逐文件刷新界面；
- “传输记录”卡片在任务运行期间隐藏，只在暂停、中断或完成后显示；
- 应用停留在前台执行正式传输时自动保持屏幕常亮，任务结束、暂停或离开页面生命周期后立即解除；
- 剩余时间不再按“启动至今耗时/百分比”推算；实际传输开始 10 秒后，以近 10 秒平均速度计算 `(总量 - 已传输量) / 速度`，以后每 10 秒刷新一次；
- 修复 rsync 在 itemize 行前附加诊断前缀时解析不到差异的问题，并记录每次任务的原始输出行数、已解析项目数和退出码；
- 修复设备策略卡片被长策略文字挤压后设备名称逐字竖排的问题；名称、地址和策略现在分行显示；
- 差异预览按钮移到结果面板上方，点击后立即显示准备、扫描、完成、无差异或失败状态，不再出现操作后看似无反应；
- 对方发起差异预览时，本机顶部状态栏和同步页会持续显示“对方正在扫描差异文件夹”，结束后自动清除；
- 修复自动准备双向 `send/receive` 模块后立即检查 PID 导致误报“rsync 未保持运行”的启动竞态；
- 重启服务时等待旧 rsync daemon 完全退出并确认端口释放，必要时只强制结束经过配置路径校验的本应用旧进程；
- 服务启动同时检查 PID 与监听端口；失败时自动读取最新 `rsyncd.log`，把 bind、权限、配置等具体错误显示到双方日志和结果框；
- 修复 TCP 健康探测占用 rsync daemon 唯一连接槽、紧接着的预览或传输报 `max connections (1) reached` 的问题；本机改为读取内核监听表，远端准备成功后直接进入 rsync 协议；
- 修复 300 GB、约 1.2 万文件目录在双向差异预览时因 `--checksum` 对双方全部文件逐个读取而长时间没有输出的问题；双向预览改用大小和修改时间快速筛选；
- 修复取消预览只关闭 Java 端管道、ROOT rsync 子进程仍残留的问题；取消时校验 PID 后发送 INT，超时后强制结束，并清理 PID 文件；
- 修复 Android 杀死应用进程后 ROOT `librsync.so` 脱离父进程继续占用 CPU：任务启动时创建独立生命周期看门狗，检测应用 PID 消失后终止传输进程和本应用 daemon；下次启动还会按 PID、配置路径和应用安装路径清理遗留进程；
- 生命周期看门狗使用独立脚本路径和 PID 标记；重复任务复用同一实例，异常退出后同时清理 rsync、daemon 与孤立的本应用 `sh` 看门狗；
- 前台传输任务从最近任务中被移除时立即转为暂停并终止底层 rsync，不再依赖 ViewModel 的 `onCleared`；
- 新增跨重启持久诊断日志，保留当前与上一段日志；可从日志页导出 UTF-8 文本或复制 ADB 读取命令；
- 对端扫描/同步结束后保留 8 秒完成提示，不再从“正在扫描”状态直接闪退消失；
- 修复服务准备阶段提前创建“正在预览/同步”状态、随后收到真正任务状态时旧超时协程误清除新状态的问题；任务活动消息增加唯一 taskId 并去重重复 UDP 包；
- 发起端会把 rsync 识别出的当前文件路径同步到对端，对端的详情面板可显示“对方扫描/正在传输”的文件与目录；
- 每个设备策略标签右上角显示在线状态圆点：定时发送轻量 UDP 单播在线探测，45 秒内收到回应显示绿点，否则显示红点；
- 传输进度同步显示在系统通知栏，前台 `dataSync` 服务配合 CPU/Wi-Fi 锁保持后台传输；
- 支持暂停、连接中断自动暂停、跨进程重启继续传输，并可单独删除传输记录；partial 分片和用户文件不会随记录删除；
- 传输记录按设备隔离，本机重操作互斥；被动接收端同样进入前台保活，任一端已有任务时拒绝并发启动；
- RootShell、界面状态和持久日志均采用有界或节流更新，避免大量文件时内存、磁盘写入和 Compose 重组持续增长；
- 局域网关键 UDP 请求自动重试并在 2 分钟后清理；重复配对包不会重复弹窗，重复准备包直接复用原应答；
- 完成差异预览后 30 秒内立即开始同配置传输，会复用预览的流量统计，正式 rsync 仍重新核对并传输文件；
- rsync 客户端和服务端密钥文件改为 ROOT 所有、0600 权限，修复 ROOT 模式的密钥文件校验与部分错误 10；
- rsync daemon 提供受限的 `send` 只读模块和 `receive` 只写模块，并拒绝全部删除类参数；
- 客户端命令不生成删除参数，运行时再次拦截删除选项，代码中不执行显式清理命令；
- 正式传输后只对本次实际新增或更新的文件执行 rsync `--checksum --dry-run` 零写入校验；校验失败时自动暂停，只有全部通过才标记完成并发送系统通知；
- 目标端独有文件始终保留；被更新文件的旧版本保存到目标目录下的 `.rootsync-history`；
- dry-run、partial 续传、超时和实时日志；
- 修正默认哔哩哔哩包名为 `tv.danmaku.bili`；本机接收目录不存在时必须由接收端用户确认后才会通过 ROOT 创建；
- 默认仅构建 `arm64-v8a`。

## 构建

依赖 Android SDK 36、NDK 26.3、JDK 17、Gradle 9.2 和 MSYS2（构建 rsync 时使用）。

```powershell
.\native\build-syncmeta.ps1
.\native\rsync\build-android.ps1
.\gradlew.bat :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
```

APK 输出：`app/build/outputs/apk/debug/app-debug.apk`

已构建版本：`dist/RootSync-v0.2.30-debug-arm64.apk`

## 两机使用

1. 两台手机安装相同 APK，授予 ROOT，并连接同一 Wi-Fi。
2. 两端进入“服务”，确认本机发送源、本机接收目录和监听端口，然后启动服务。
3. 进入“同步”并点击“自动扫描局域网”；点击设备，对方选择“允许连接”。
4. 为该设备选择“只发送”“只接收”或“双向同步”，再选择全部内容或指定时间至今，保存设备策略。
5. 可先运行差异预览，在详情框检查变化文件和目录，再执行零删除同步。
6. 传输可切到后台、暂停或在连接中断后继续；“删除传输记录”只删除任务记录。

自动发现和首次连接弹窗要求对方 RootSync 处于打开状态。完成配对并启动 rsync
服务后，rsync daemon 可独立运行，另一台设备可按已保存的 IP 和策略连接。

0.2.30 使用带设备控制令牌认证的局域网控制协议 v7；建议两端同时安装 v0.2.30，
以完整支持接收目录确认和等待状态显示。
