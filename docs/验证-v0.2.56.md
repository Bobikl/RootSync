# v0.2.56 启动卡顿定位与验证

## 旧版实机证据

用户连接的小米 Android 17（SDK 37）设备安装 v0.2.55-debug。
只读取日志并运行只读的身份、工具版本、目录访问检查，没有安装、重启、停止或清除应用。

- 日志两次开始检查到清理结束／公布 CHECK：约 55.8 秒、68.9 秒。
- ROOT 身份检查 107ms，rsync ROOT 版本检查 105ms，syncmeta 98ms。
- 应用身份直接检查 rsync 83ms、syncmeta 80ms，ROOT 目录访问 95ms。
- 启动清理旧实现两次枚举全机进程表，为各进程运行 tr/grep/子 shell；UI 在清理后才发布引擎能力。
- 因此主要问题是启动清理阻塞结果显示，并非原生引擎本身需要一分钟初始化。

## 修改

1. 启动清理只读取私有 runtime 下 scan、transfer、rsyncd、lifecycle-watchdog 的 PID 文件；校验进程命令属于本应用 runtime，发送信号前复核；不扫描全机进程。
2. 清理限时 2 秒，失败记录 WARN，不再隐藏已经完成的引擎检查。
3. 原生版本直接执行、ROOT 回退，短诊断每次最多 1.5 秒；传输／清单扫描不受此限制。
4. UI 分阶段展示，日志增加 PROBE_START／PROBE_END、耗时与退出码。
5. 保留协议 8 与现有配置，不修改配对或传输策略。

## 自动测试

新增 TimedProbeTest：正常返回／耗时日志、超时取消、异常转结果、父协程取消传播。
新增 StartupCleanupTest：限定 PID、无全机扫描、路径引用、拒绝共享目录。
构建结果与 APK 校验值见 dist/README.md。
