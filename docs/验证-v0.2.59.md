# v0.2.59 目录首次读取性能复查

## 根因与方案选择

用户反馈 v0.2.58 第一次进入目录仍会出现明显等待。
B 设备（TCL T807D / Android 16）只读查询 `type` 显示：`[`、`read` 是 shell builtin，`printf` 是 `/system/bin/printf` 的别名，即每次调用需创建外部进程。
上一版虽然整页仅做一次 Base64，但仍逐目录 printf，导致 100 项就启动约 100 次额外程序。这是上一版优化遗漏，并非必须等待重新授予 ROOT 权限。

对比候选方案：整页参数数组＋一次 printf 约 188ms；系统原生 find＋sort 批量枚举约 187ms。原生 find 没有额外收益且会改变隐藏目录排序，并受各系统工具选项差异影响，因此采用改动更小的参数数组方案。
最终实现进一步用固定内容的 builtin echo 输出帧头／换行；路径和目录名不经 echo、不拼接为可执行代码，只经一次固定格式 printf 与一次 Base64。ROOT 权限、物理路径边界和最终选择时权限复查保持。
不声称知道 MT 管理器的内部实现，也不引入额外常驻 ROOT 服务。

## 最终生产命令测量

提取 v0.2.58 Git 版本与本次源代码生成的命令，均通过应用身份发起 `su -c` 执行。每次新建 ROOT 命令，不使用应用目录缓存；没有清除操作系统文件缓存。统计包含 ADB 调用开销，不能等同于 APK 冷启动或 UI 帧耗时。
每组新版执行 3 次，新旧完整目录名／顺序／分页标记均一致：

| 目录／页 | 旧版 | 新版三次 | 中位数 |
|---|---:|---|---:|
| 内部存储根目录，17 项 | 422ms | 125 / 125 / 125ms | 125ms |
| Android/data，22 项 | 516ms | 125 / 140 / 125ms | 125ms |
| 下载目录第 1 页，100 项 | 1797ms | 156 / 125 / 125ms | 125ms |
| 下载目录第 2 页，100 项 | 1938ms | 125 / 156 / 141ms | 141ms |
| 下载目录第 21 页，83 项 | 1593ms | 172 / 172 / 156ms | 172ms |
| 同目录仅校验，不列子目录 | 157ms | 109 / 109 / 125ms | 109ms |

实际耗时受设备、目录大小、ROOT 管理器和负载影响。

## UI 与自动验证

200ms 防闪烁仅控制加载提示显示时机，实际 busy 状态立即生效；取消和选取权限检查不变，慢请求超过 200ms 仍显示等待。
回归断言每页仅一个 printf，目录循环内没有 printf，且保留整页编码；新增满 100 项中文、空格、引号、换行、制表符跨页完整性测试。
最终构建、测试数量、APK 签名与哈希见 dist/README.md。

只读取手机状态和目录，未安装、重启应用或写入手机文件；新版 APK 完整 UI 体验由用户安装后验收。协议 9 未变，可与 v0.2.58 互通。
