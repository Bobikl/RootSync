## 尚需两台 ROOT 手机验证

当前 adb 没有连接设备。以下为实机验收清单，不等同于已完成测试：

1. KernelSU 已授权冷启动：应直接显示 ROOT 已授权，不出现等待 Magisk 的提示；手动拒绝后请求 ROOT 应能重试。
2. Magisk 已授权／未授权：分别验证自动检查与手动授权、退出及再次进入。
3. 选择 Android/data 下中文目录；上一级、最近目录、分页和关闭弹窗应正常，取消不能影响同步任务。
4. A 选择从 B 接收，B 自动变发送；再由 B 选择双向，A 变双向。离线变更后重连，双方确认状态一致。
5. 双方同时改方向时最终收敛；切换另一个配对设备后，前一设备消息不能修改当前设备路径。
6. 接收根目录不存在：预览不能创建目录；正式执行必须弹窗确认。拒绝后不得开始写入。
7. 同时间异大小、严格模式同时间异内容、文件/目录类型冲突：完整计划显示冲突，正式任务不得开始传输。
8. 双向混合新旧文件：同一路径只进入一个方向，不因先接收后发送产生重复计划。
9. 大目录严格扫描、远端等待确认、正在传输时取消：两端应退出对应任务，下一次可重新扫描。
10. 大于 400 项的差异：完整计划可逐页查看；动态摘要截断不得影响总数或实际执行清单。
11. 暂停后切换已确认方向／路径再继续：使用当前策略重新生成计划，不恢复旧策略。
12. 覆盖安装保留设备配置；两端均需安装协议 8 的 v0.2.55。

Linux 原生全遍历 fixture 已提供于 native/test-directory-manifest.py，
当前环境仅运行 Windows SHA-256 和 Kotlin 解析 fixture；未伪称完成手机双端端到端测试。
