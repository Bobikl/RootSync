## B 设备空间故障

2026-10-01，已连接 TCL T807D / Android 16，应用 v0.2.57-debug。
日志：21:58:35 服务端启动成功；21:58:39 报“本机无法读取接收目录剩余空间”。本次任务在日志中的方向为 BIDIRECTIONAL。
代码使用普通应用进程的 StatFs，查询 Android/data 下其他应用目录会被拒绝，而 ROOT 扫描和同步可以访问。

只读复现：
- 应用身份 statfs：Permission denied，93ms。
- ROOT 同一路径 statfs：110ms，可用块数 20408523、块大小 4096，约 83.59GB。
- 新查询格式实机执行：125ms，`ROOTSYNC_SPACE=20408392:4096`。可用量随设备后台活动变化。

修复使用独立 ROOT 通道、3 秒限时，解析可用块而非总块／空闲块；保留 0 字节，拒绝异常、重复、溢出结果。只查询实际接收目录；失败时两端均暂停任务，不跳过容量检查。

## 双端共享策略

范围、起始时间和严格比较模式使用同一版本确认机制；同版本不同比较模式不能当作重复确认。双方方向互补，范围／有效起始时间／比较方式相同，各自路径不变。
比较模式加入配对消息、策略消息、每设备持久化与排队的远端更新；切换设备／重启恢复对应模式。旧配置缺少模式字段时继承旧全局值并废弃旧确认，重新协商。
范围或比较修改自动发出，不要求点保存；任务进行时界面不可修改，收到对端更新延后处理。任务准备再次核验范围、时间、模式。
控制协议从 8 升到 9；双方必须升级，避免旧版本忽略模式字段后错误确认。

## ROOT 文件夹性能

旧实现每个目录名分别经过 Base64 和 tr 子进程；新实现每页仅一次 Base64，NUL 分帧，仍保留 UTF-8、特殊字符、分页、真实路径边界与最终写权限校验。
新旧代码中生成的命令在 B 设备上以相同应用 ROOT 身份执行，只读比较目录输出：

| 目录 | 旧命令 | 批量命令 | 项目数 |
|---|---:|---:|---:|
| 内部存储根目录 | 1077ms | 453ms | 17 |
| Android/data | 1328ms | 563ms | 22 |
| B 站下载目录 | 5389ms | 1938ms | 100 |

三个目录的结果和分页标记完全一致；实际耗时受目录规模和设备负载影响。
另加浏览器生命周期内最多 16 页／15 秒缓存，缓存页显示标签；刷新清除该目录缓存，关闭清空缓存；最终选择不使用缓存权限结果。
